## What the code actually claims, read directly

**Bulk-mail exclusion** (`connectors/gmail.mjs` `DEFAULT_QUERY`):

```js
export const DEFAULT_QUERY =
  "-in:chats -in:drafts -in:spam -in:trash " +
  "-category:promotions -category:social -category:forums -category:updates";
```

This excludes Gmail's own `promotions`/`social`/`forums`/`updates`
categories at the Gmail API query level (server-side, before anything is
fetched), not by any local heuristic. The seeded-mailbox test below is the
right way to prove this because it makes "how much of the seeded newsletter
mail got in" a countable assertion instead of a spot check.

**Resumability** (`cmdIngestRemote`'s Gmail branch, `brain.mjs`):

- Each message is keyed `sourceName:id` in the local ingest state file
  (`.brain-ingest-<source>.json`), with `state.done[key]` recording the
  last accepted `version` (the message's Gmail `historyId` at ingest time,
  falling back to the message id).
- A message already in `state.done` with the same version is treated as
  `unchanged` and is not re-sent (`brain.mjs:6082`
  `state.done[key] === r.version`).
- The Gmail history cursor (`state.history_id`) is written to disk only
  **after** every batch in the run has been accepted by the server
  (`pendingCursor` is applied at the end, not per-message). If the process
  dies mid-run, already-accepted messages stay recorded in `state.done`
  (so a resumed full or incremental pass will not re-upload them), but the
  history cursor itself does not silently advance past mail the killed run
  never actually finished handling.
- Net effect: a full re-list after a kill should re-walk the same message
  ids, but every one already accepted resolves to `unchanged` via the
  `state.done` check, which is what "zero duplicate documents on resume"
  actually rests on in this code. This has never been run against a real
  kill, which is exactly why the plan asks for it as a proof step, not an
  assertion.

## Commands, in the plan's required order

Run every step from a real interactive terminal (hidden Cloudflare-token

### Step 1 — connect Google, seeded test mailbox first

```bash
# One time, in an interactive terminal. Use a throwaway/test Google
# account you control, planted beforehand with:
#   - a handful of real-looking financial emails (a fake invoice, a bank
#     notice, a signed-document email) so there is something the brain
#     SHOULD find
#   - several newsletters/marketing sends (subscribe the test account to
#     3-5 real newsletters, or forward some in) so DEFAULT_QUERY's
#     exclusion has something real to prove against
brain connect google --scopes gmail

brain sources <manifest> --add gmail-seed-test --kind gmail

brain ingest <manifest> --from gmail --source gmail-seed-test
```

**Expected, if the code does what it claims:** the run summary line
(`brain.mjs:6127`, `"N scanned; N document(s) prepared..."`) should show
scanned count roughly matching total seeded mail, with the newsletter/
marketing messages never appearing at all (excluded at the query, so they
are not even scanned) — NOT filtered-and-skipped, genuinely absent from the
scan count. Confirm the specific claim the plan asks for by asking the
brain directly:

```bash
brain ask <manifest>
# ask something only the newsletter content could answer, e.g. a phrase
# unique to one of the planted newsletters. The cited answer should show
# ZERO citations to that content.
```

### Step 2 — bounded run against a real mailbox

```bash
# Only after step 1 is clean. Still bounded — this is the scale proof,
# not an unbounded first run against a real inbox.
brain connect google --scopes gmail
brain sources <manifest> --add gmail-real --kind gmail
brain ingest <manifest> --from gmail --source gmail-real --limit 500
```

Record the exact scanned/prepared/unchanged/skipped counts printed.

### Step 3 — resumability: kill mid-ingest, restart, prove zero duplicates

```bash
# Start a larger bounded run in the background, or ready to Ctrl-C:
brain ingest <manifest> --from gmail --source gmail-real --limit 2000
# Kill it partway through (Ctrl-C, or `kill` the process) once the
# progress counter has clearly advanced but before it would finish.

# Note the state file before resuming, for the record:
cat .brain-ingest-gmail-real.json | head -c 400

# Resume with the SAME command, no --reset:
brain ingest <manifest> --from gmail --source gmail-real --limit 2000
```

**What to check:** the second run's `unchanged` count should account for
everything the first run actually got through before it died (proving
`state.done` resumed correctly), and the total document count in the brain
afterward (`brain sources <manifest>`, or a direct `brain ask` count
question) should equal what one clean uninterrupted run would have
produced — not double-counted. This is the one claim in the whole package
that has never been proven end to end on the Gmail path specifically, per
the plan, so record the exact before/after counts, not just "looked fine."
