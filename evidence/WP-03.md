## What was built

- `ingest/sms-backup.mjs` (new): two independent parsers sharing one file
  because both feed platform `sms`:
  - **SMS Backup & Restore** (the common Android backup app): a lightweight
    attribute-regex XML reader for `<sms .../>` elements (no XML dependency
    needed — the schema is simple, well-known, and always double-quoted
    attributes). Reads `date` (Unix epoch milliseconds), `address`,
    `contact_name`, `type` (1=received, 2=sent), and `body`. `<mms>`
    elements are counted but not parsed (stated plainly, not silently
    dropped). One file can hold every conversation the phone has, not just
    one, so parsing groups by `address` into separate threads and sorts the
    whole file chronologically before handing rows to the sessionizer.
  - **Google Voice Takeout**: a regex reader for Google's own `hChatLog`
    HTML microformat (`<div class="message">` blocks with an
    `<abbr class="published" title="ISO-8601">`, a `<cite class="sender">`
    naming the contact, and a `<q>` holding the message text). A call or
    voicemail record shares the same page template but has no `<q>`, so it
    naturally parses to zero rows rather than being misread as a
    conversation.
  - Neither format has WhatsApp's date-ambiguity problem: both write
    unambiguous machine timestamps (epoch ms, or full ISO-8601 with a UTC
    offset), so there is no locale guess to make here — only correct
    parsing, which is what the tests below check.
- `ingest/run.mjs`: `prepare()` now also content-sniffs `.xml` files for the
  SMS Backup & Restore root tag and `.html`/`.htm` files for the `hChatLog`
  marker, exactly the same interception pattern WP-02 added for `.txt`
  WhatsApp exports — before falling through to the generic XML/HTML text
  extractors, which remain correct for every other `.xml`/`.html` file.
- `brain.mjs`: no changes needed beyond what WP-02 already added — the same
  `envelopes` (plural) branch in `cmdIngest.prepareOne` handles this too.

## What was NOT done, and why

- Same live-infra gap as WP-01/WP-02: "a question about fixture content
  returns a cited answer" needs a deployed brain and `brain ask`, which this
  session has no live Cloudflare credentials to stand up. The dry-run above
  proves the correct documents would be sent with correct content; it does
  not prove server-side retrieval.
- MMS entries in an SMS Backup & Restore export are counted but not parsed,
  stated in the module's own header comment and surfaced in the skip reason
  (`skippedMms`). A real MMS parser (multi-part, often containing an image)
  is a reasonable follow-up but out of this pass's scope.
- The iPhone-side of SMS (Text Message Forwarding riding in on the iMessage
  connector) is Wave 1 scope (WP-06/WP-09), not this package.
