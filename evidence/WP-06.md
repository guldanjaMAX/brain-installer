# WP-06 evidence — iMessage Mac capture connector (`brain connect imessage`)

Date: 2026-08-27. Branch `wave1/wp06-imessage`, built in an isolated worktree
off `wave0/connector-gaps`. Written to the tracked `evidence/` directory per
the plan's durability note (planning/ is gitignored and would not survive a
fresh clone).

## What shipped

- `connectors/imessage.mjs` — the capture core: incremental chat.db reader
  (ROWID watermark, GUID identity), the attributedBody typedstream parser
  ported to Buffer slicing (all three length-prefix branches + the
  mostly-replacement-characters bail-out), iMessage-vs-SMS classification off
  `handle.service` case-insensitively, atomic owner-only state carrying BOTH
  the watermark and the sessionizer snapshot, immediate re-poll on a full
  5000-row page, a stale-session sweep so dormant threads become searchable,
  and access failures NAMED: `full_disk_access_denied` (EPERM/EACCES) distinct
  from `chat_db_missing` (ENOENT) distinct from a locked/unreadable database.
  The snapshot-copy fallback classifies its own permission errors and copies
  into an owner-only temp dir it removes on close (the reference left a
  world-readable /tmp copy behind).
- `operations/drive-scheduler.mjs` — generalized into a parameterized
  connector scheduler (spec object). The Drive spec reproduces prior behavior
  exactly, including a byte-identical config-hash payload; every previously
  exported Drive-named function still exports; all 69 existing drive-scheduler
  tests pass WITHOUT EDITS.
- `operations/imessage-scheduler.mjs` — the every-minute
  StartCalendarInterval LaunchAgent (short ticks + lockf, per the plan's
  decision (a); NOT a KeepAlive daemon), whose tick child is
  `brain ingest <manifest> --from imessage`.
- `brain.mjs` — `brain ingest --from imessage` (also `--dry-run`, `--limit`,
  `--reset`, `--chat-db`, `--flush-sessions`), `brain connect imessage`
  (FDA verified by a REAL read before anything installs; initial history load
  in the foreground with counts; then the agent + freshness expectation), and
  `brain disconnect imessage` — the first disconnect verb, removal reachable
  even when the corpus flag is off, with a best-effort open-session flush and
  expectation clear. Envelope source_type is rewritten to the load's name so
  `brain forget --source imessage` genuinely scopes to these documents.
- Worker `SOURCE_KINDS` accepts `imessage`; support journal learns the
  `disconnect` command and `imessage` source; manifest schema + template
  document `corpora.imessage` and `operations.imessage_capture_cron`.
- Matrix row + section moved to Built with the Mac-only and scheduler-tick
  truths stated; CHANGELOG 0.1.22 in owner voice; version pinned everywhere
  `test/current-version.test.mjs` checks.

## Decisions taken (as directed by the plan/brief)

- Scheduler = generalized drive-scheduler (option a), short ticks every
  minute. No KeepAlive daemon, no ported bash locking.
- No Postgres/person-graph logic from the reference was ported; the ONLY
  output path is `MessageSessionizer` envelopes through the shared
  `/api/admin/brain/ingest/batch` push (so the worker's credential gate runs
  on every document — nothing bypasses it).
- Message GUID is the durable source identity (session documents are keyed
  by their first message's GUID).
- All fixtures are invented (Alex Rivera / Jordan Lee / +1555… personas,
  consistent with test/fixtures); the synthetic chat.db is built inside the
  tests with node:sqlite. No real chat data anywhere, including comments.

## What could NOT be proven in this environment, and why

1. **A genuine launchd TCC (Full Disk Access) denial.** TCC decisions are
   per-binary, made by macOS for the real launchd spawn chain; no test can
   grant or revoke them. The EPERM/EACCES class the classifier keys on is
   exercised through a directory the test user cannot traverse, which
   produces the same errno path — but the real "launchd-spawned node lacks
   the grant" event needs a real Mac session. The connect flow was built so
   this is verified live by construction: it refuses to install until a real
   read of the real chat.db succeeds.
2. **Capture against the real ~/Library/Messages/chat.db.** This session must
   not read the machine owner's actual messages, and tests never touch that
   path. Everything runs against a synthetic chat.db with the same schema
   subset and invented personas.
3. **A live worker round trip** (real credential gate, real Vectorize, real
   `brain sources` freshness rows). The batch endpoint, receipts and
   expectation calls are driven against scripted fakes returning the real
   receipt shapes — the same boundary every other connector test in this repo
   uses. The gate itself runs server-side on the shared endpoint this
   connector pushes through, so no new gate code was written or needed.
4. **The locked-database snapshot fallback against a genuinely live-locked
   db.** Its error paths (including its own EPERM naming) are tested; a real
   Messages.app holding the database open is a live-Mac-only condition.
5. **The "newly sent test message appears within one capture interval"
   acceptance bullet, end to end on a real Mac.** The pieces are proven
   separately (a tick spawns the capture child; a capture pass picks up new
   rows; the tick fires every minute), but the live composite needs a real
   Mac with FDA granted.

### The exact live verification for a real Mac (for James / Fable to run)

```bash
# in the client checkout, with corpora.imessage.enabled=true in the manifest
node brain.mjs connect imessage <manifest>       # walks FDA, loads history with counts, installs the agent
# send yourself a text from another device, wait ~90s
node brain.mjs sources <manifest>                # imessage row fresh, document count grown
node brain.mjs ask <manifest>                    # ask about the test text, expect a cited session
node brain.mjs disconnect imessage <manifest>    # agent removed, open sessions flushed
```
